**Parent:** [Canonical roadmap](crm-scoped-delivery-plan.md).  
**Execution:** Exclusively **Phase 7, the last implementation phase**. This planning task runs no application tests or runtime checks. All current acceptance statuses are **BLOCKED / not executed**.

## 1. Four verdicts, not one ambiguous “done”

| Verdict | Required proof | Does not establish |
| --- | --- | --- |
| V1 Local coexistence | A02/A03/A08/A10 local synthetic routing/record/storage restart portions, measured A12 local interference; honest target/toolchain evidence A01/A15 | Complete scoped features, intended external worker, actual live domains or production readiness |
| V2 Complete scoped features | All A01–A12 and A14/A15 relevant synthetic feature/component/operation gates, including **A11 on intended approved Vultr worker**, generated objects, full broker negatives, dashboard/calculator choices and required component UAT | Live-domain pass or production deployment approval |
| V3 Actual live-domain acceptance | A13 and approved live-safe observations of A02/A03/A09–A12/A15 on actual intended HTTPS hostnames/release; V2 safety prerequisite | Load/soak or every production-readiness claim merely because host returns 200 |
| V4 Production readiness | V2, supported production provider/schema/privilege/network paths, assigned operations/security/legal owners, approved numeric budgets, A14 backup/scoped restore/release rollback, real-instance evidence and required final-origin auth; A15 explicit sign-offs, with V3 separately reported | Permission to publish, bill resources, import real data or run unapproved soak |

V4 may assess release readiness before cutover; actual live remains V3 only after approved publication/domain evidence. Any required blocked worker/support/threshold/approval finding blocks V2/V4. Local V1 results may be reported separately but never relabeled full v2 delivery. If a readiness statement omits an unapproved yet required real-instance/soak case, it must remain **conditional/BLOCKED**, not production-ready.

Native brokers are members/users: “Broker CRUD” in target UAT is interpreted as approved native identity/membership/assignment lifecycle, not a fourth custom object. No inventory/inbound integration gate is required or permitted in v2; deferral is explicit approved scope, not a hidden skipped required test.

## 4. Final order, failure policy and evidence

Apply [Autoscale environment extensions E01–E08](crm-scoped-replit-environments.md)
to the relevant A01–A15 rows. They make replica, cold-start, toolchain, transport,
public-port and private-photo persistence evidence explicit without moving tests
out of final Phase 7 or claiming unverified native variable/schema names.

1. Resolve decisions/approve command limits/targets first. Confirm target through supported identity flows, names only in evidence.
2. In Phase 7 run static/build validation and authorized fixtures, then capture website/Payload baseline before CRM activity. A known failing homepage/font/media check blocks its acceptance; baseline owner acknowledgment is not a waiver of unchanged-site requirement.
3. Execute one clean native signup with sanitized request/auth/activation state; diagnose supported specific cause. Preserve failed scope. Fixes and any further clean signup/recovery fixtures need approved scope and updated artifacts.
4. Complete component UI/API positive/negative UAT, native Vultr/storage/queue acceptance, then controlled shared-resource/failure/restore/rollback/load. All remain within final phase.
5. Synthetic safety and restore results precede any separately approved production schema/publish/domain action. Live-safe checks add evidence, not substitute for synthetic safety. Extended soak needs fresh duration/cost approval.
6. Repairs invalidate every affected dependent result (e.g. ACL changes invalidate counts/search/export/attachments; gateway/auth changes invalidate origins/live routes; schema/queue identity changes invalidate persistence/worker/recovery). Record new source/manifest and rerun relevant cases before verdict, in this final phase.

One evidence row per case: acceptance ID/subcase, environment/resource alias, timestamp/timezone, website/fork/lockfile/artifact identities, method/command/side-effect approval, synthetic fixture IDs, exact expected/observed result, numeric measurements, redacted evidence path, PASS/FAIL/BLOCKED, responsible signer and repair invalidations. Compact tracked manifest; large output ignored/approved durable storage; no PII/token/credentials/cookies/signed URLs.

Component sign-off is required for **Next.js website**, **Payload CMS**, **CRM frontend/API**, **native Vultr worker**, plus shared release/DB/gateway operations. A shell build, unauthenticated screenshot, HTTP-200 health route, schema table count or synthetic lookup effect cannot replace authenticated UI/API and authorization evidence.

Documentation verification of this plan is separate and happens last in this documentation task. No app suites/static validation/smoke/provider/account/rehearsal were needed or authorized to produce it.
